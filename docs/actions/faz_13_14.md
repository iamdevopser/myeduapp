# 3. P10-A — MOBILE BOTTOM NAVIGATION

Mobil ekranlarda mevcut sidebar/drawer yapısı ile uyumlu bir bottom navigation deneyimi oluştur.

Öncelikle mevcut navigation mimarisini incele ve şu soruları cevapla:

* Hangi roller bottom navigation kullanmalı?
* Her rol için hangi ana destination'lar gösterilmeli?
* Kaç destination doğrudan gösterilmeli?
* Fazla destination'lar nasıl erişilebilir kalmalı?
* Mevcut drawer/sidebar ile bottom navigation nasıl birlikte çalışmalı?

## Kurallar

Bottom navigation:

* yalnızca uygun dar ekranlarda aktif olmalı,
* desktop davranışını bozmamalı,
* tablet davranışını gereksiz yere değiştirmemeli,
* role-aware olmalı,
* mevcut route/tab/state yapısını kullanmalı,
* authorization kurallarını bypass etmemeli.

Çok fazla item bottom navigation'a koyma.

Gerekirse ana destination'ları bottom navigation'da tut ve diğerlerini mevcut drawer / More alanında bırak.

Aşağıdaki genişliklerde kontrol et:

* 360 px
* 390 px
* 430 px

Bottom navigation'daki her destination gerçek mevcut workspace/route/tab yapısına bağlanmalıdır.

Sadece görsel bir navigation oluşturma.

# 4. P10-B — SETTINGS NAVIGATION CONSISTENCY

P9 auditinde Student / Parent / Secretary sidebar/drawer içinde Settings shortcut eksikliği tespit edilmiştir.

* `/settings` route'u ile navigation erişimi aynı authorization kurallarına uymalı.
* Admin ve Teacher mevcut Settings davranışlarını kaybetmemeli.

Mevcut role-based Settings yapısını bozma.

# 6. P10-D — TEACHER DISPLAY NAME SERVICE GUARD

P9 technical debt:

> Teacher display-name değişimi UI katmanında doğrudan `db.setSetting` kullanıyor.

Bu işlem servis katmanında korunmalıdır.

UI'dan doğrudan:

```dart
db.setSetting(...)
```

gibi yetki gerektiren bir işlem yapılmamalıdır.

Mevcut Settings/Service mimarisini incele ve display-name değişimini uygun servis metoduna taşı.

Örneğin mevcut mimariye uygunsa:

```text
setTeacherDisplayName(...)
```

benzeri bir servis metodu kullanılabilir.

Ancak yeni servis yalnızca gerçekten gerekli ise oluşturulmalıdır.

Servis katmanı:

* authorization kontrolü yapmalı,
* yetkisiz roller için uygun exception üretmeli,
* UI'dan bağımsız olarak güvenli olmalıdır.

Mevcut:

* `AuthorizationService`
* `TeacherSettingsAccessDeniedException`
* `canManageTeacherWorkspaceSettings`

gibi P9 yapılarını mümkün olduğunca yeniden kullan.
